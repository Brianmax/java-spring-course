Básico · Programación orientada a objetos

Un paradigma es una forma de diseñar y organizar un programa. En POO, modelamos objetos que reúnen datos (estado) y acciones relacionadas (comportamiento).

Comportamiento: acciones del objeto, como calcular el total.

Fundamentos de la POO

La POO organiza el programa alrededor de objetos: reúnen estado, comportamiento y relaciones.

Piezas de una clase

Clase: descripción para crear objetos.

Objeto: ejemplar concreto con identidad.

Atributos / estado: datos que conserva el objeto.

Métodos / comportamiento: acciones o consultas.

Constructor: prepara el objeto al crearlo.

Principios

Abstracción: mostrar lo necesario para usar algo.

Encapsulamiento: proteger estado y aplicar reglas al cambiarlo.

Herencia: especializar una clase reutilizando otra.

Polimorfismo: misma operación, respuesta propia del objeto.

Relaciones y contratos

Asociación: objetos que se conocen o colaboran.

Agregación: una parte que puede vivir por separado.

Composición: una parte pertenece a un todo y depende de él.

Interfaz / contrato: capacidades que una clase se compromete a ofrecer.

Básico · Unidad 4 · Estado protegido

Encapsular: cambiar el stock mediante operaciones

class Inventario {
    private int stock = 5;
    public boolean retirar(int unidades) {
        if (unidades <= 0 || unidades > stock) return false;
        stock -= unidades;
        return true;
    }
    public int consultarStock() { return stock; }
}
Regla y resultados · cada intento parte de 5

retirar(2) → true · stock queda en 3.

retirar(8) → false · stock sigue en 5.

Encapsular protege el estado interno y permite cambiarlo mediante operaciones que aplican reglas. stock es privado; retirar y consultarStock son públicos. Un getter o setter puede ser válido si encaja con las reglas del modelo.

Básico · Unidad 5 · static y final

final fija la referencia; static pertenece a la clase

final class Producto {
    static final int MAX_CODIGO = 12;
    private final String codigo;
    Producto(String codigo) { this.codigo = codigo; }
    String getCodigo() { return codigo; }
}
Producto A: CU-10
Producto B: CU-20
Compartido: MAX_CODIGO = 12

Declarar el límite no valida la entrada. Una referencia final no hace inmutable al objeto referido.

Atributo normal: una copia lógica por instancia. static: miembro de la clase. final impide reasignar campo; una clase final no se extiende.

Básico · Unidad 6 · Herencia

Herencia: reutilizar y especializar una clase

class Entrega {
    public int diasEstimados() { return 5; }
}

class EntregaExpress extends Entrega {
    // Hereda diasEstimados()
}

EntregaExpress express = new EntregaExpress();
express.diasEstimados(); // 5

¿Qué significa?

La subclase EntregaExpress hereda los métodos accesibles de la superclase Entrega. Así puede reutilizarlos y añadir o cambiar su comportamiento.

Aquí: express puede llamar diasEstimados() aunque ese método esté escrito en Entrega.

extends declara la relación “es una”. Los constructores no se heredan; el siguiente ejemplo especializa el plazo con @Override.

Hereda solo si la subclase también cumple las promesas de la clase base; no uses herencia únicamente para copiar código.

Básico · Unidad 6 · Sobrescritura

Sobrescribir una operación con @Override

class Entrega {
    public int diasEstimados() { return 5; }
}
class EntregaExpress extends Entrega {
    @Override
    public int diasEstimados() { return 1; }
}

Misma petición

Objeto Entrega → 5 días

Objeto EntregaExpress → 1 día

La firma coincide; @Override pide al compilador revisar ese hecho.

Los atributos heredados no se reemplazan dinámicamente como los métodos de instancia.

Básico · Unidad 6 · Inicialización de subclase

super reutiliza la parte heredada

class Entrega {
    private final String destino;
    Entrega(String destino) { this.destino = destino; }
}
class EntregaExpress extends Entrega {
    EntregaExpress(String destino) {
        super(destino);
    }
}

super(destino) inicializa primero la parte base. super.metodo() puede llamar su implementación.

Los constructores no se heredan. final puede impedir extender una clase o sobrescribir un método.

No extiendas solo para reutilizar código: ¿una entrega programada cumple el contrato general?

Intermedio · Unidad 9 · ampliar el contrato

Métodos default y static

Dos métodos con propósitos distintos 
interface Notificador {

    static boolean esValido(String texto) {

default

Da una operación heredable que usa el contrato; la clase puede sobrescribirla.

static

Pertenece a la interfaz y se llama como Notificador.esValido(...).

Intermedio · Unidad 11 · contratos de igualdad

equals y hashCode deben contar la misma historia

CodigoProducto compara el valor
final class CodigoProducto {
    private final int valor;
    CodigoProducto(int valor) { this.valor = valor; }
    @Override public boolean equals(Object otro) {
        return otro instanceof CodigoProducto c
            && valor == c.valor;
    }
    @Override public int hashCode() {
        return Integer.hashCode(valor);
    }
}

Si dos códigos son iguales, deben tener el mismo hash.

Hashes iguales pueden colisionar: una colección basada en hash verifica también equals.

Si redefiniste equals, redefine también hashCode: HashSet y HashMap dependen de ambos.

class StockInsuficienteException extends RuntimeException {
    StockInsuficienteException() { super("Stock insuficiente"); }
}
class Inventario {
    private int stock = 5;
    void retirar(int n) {
        if (n <= 0) throw new IllegalArgumentException();
        if (n > stock) throw new StockInsuficienteException();
        stock -= n;

    int consultarStock() { return stock; }
}

throws

En una excepción verificada, la firma puede declarar, por ejemplo: void leer() throws java.io.IOException.

La excepción de stock extiende RuntimeException, así que no exige declararla en la firma.

Intermedio · Unidad 12 · tipos de excepción

Elegir el contrato de error

Dentro de main · Inventario de la diapositiva anterior
Inventario inventario = new Inventario();
try {
    inventario.retirar(8);
} catch (StockInsuficienteException error) {
    System.out.println(error.getMessage());
} finally {
    System.out.println("Intento terminado");
}

Verificada

Una subclase de Exception que no sea RuntimeException: se captura o se declara con throws.

No verificada

RuntimeException y sus subclases no obligan a capturar ni declarar.

El catch informa el rechazo; quedan 5 unidades. finally se ejecuta al salir del bloque, salvo terminaciones abruptas de la JVM.

Para recursos que implementan AutoCloseable, try (Recurso r = abrir()) { /* usar r */ } cierra el recurso automáticamente. Es una forma esquemática: cada recurso define cómo abrirse y cerrarse.

Avanzado · Unidad 15 · Observer · aviso síncrono

Observer: registrar y avisar a los interesados

Fragmento con import java.util.List y java.util.ArrayList
interface ObservadorPedido {
    void actualizado(String estado);
}
class Pedido {
    private final List<ObservadorPedido> lista
        = new ArrayList<>();
    void suscribir(ObservadorPedido o) { lista.add(o); }
    void retirar(ObservadorPedido o) { lista.remove(o); }
    void avisarConfirmacion() {
        for (ObservadorPedido o : List.copyOf(lista)) {
            o.actualizado("Confirmado");
        }
    }
}

Qué ocurre

La llamada es síncrona: cada observador corre antes de salir de avisarConfirmacion.

Retíralo al terminar su interés. Si uno lanza excepción, la iteración se interrumpe.

Este ejemplo emite el aviso de confirmación. Cambiar el estado y reservar stock son pasos previos; si un observador falla, este recorrido se detiene.
